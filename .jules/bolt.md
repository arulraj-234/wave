## 2025-02-28 - Isolating high-frequency React State updates\n**Learning:** The 'progress' state triggered by <audio> element timeupdate events causes catastrophic re-rendering when placed inside a top-level Context Provider. When 'progress' updates 4+ times a second, it bypasses memoization for all consumers, effectively rendering the entire DOM tree repeatedly during audio playback.\n**Action:** Always decouple high-frequency primitive state updates (like audio progression or scroll position) from application-wide context providers. Instead, export refs (like 'audioRef') from the Context and manage the fast-updating primitive locally inside the specific component (like BottomPlayer) that actually needs to render it.
