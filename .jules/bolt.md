## 2024-05-20 - Global State Re-render in PlayerContext
**Learning:** Storing rapidly updating variables like `progress` (tied to `audio.timeupdate` which fires ~4 times/second) inside a global React Context provider (e.g., `PlayerContext`) causes a massive performance bottleneck. Every component that consumes the context (even if they don't explicitly use the `progress` variable, or use `React.memo` without resolving the context dependency) is forced to re-render constantly during audio playback.
**Action:** When a global state needs to provide access to rapidly updating data to only a few specific components (like `BottomPlayer` needing `progress`), expose a mutable reference (e.g., `audioRef`) instead of state variables in the Context. The components that need the real-time data can then attach their own event listeners and manage local state, isolating the re-renders to only the components that visually change.
